## 样本与可重复条件

`quality-v1.json` 包含 12 条明确标注为合成的独立事件、14 段证据、3 个实体和 40 道题。所有来源使用 `example.invalid`，不代表真实新闻，不访问外部网站。完整内容 SHA-256：

`57cd0133455918a8bb26e367469e39fe3c2b9a3e1da3b54c5c2000c1bc6af5e6`

冻结以后不能修改原文件再沿用同一版本；改题、改数据或改预期必须新建版本并保留原对照记录。`scripts/research_quality.py` 同时检查固定摘要、证据摘录摘要、请求范围映射，以及独立的分类、日期、比较、实验和实体歧义预期。它不加载应用配置、不访问数据库或模型。

| 类别 | 题号 | 主要目标 |
| --- | --- | --- |
| 事件解释 | Q01–Q06 | 事实解释、差值、产品与公司区分、避免扩大结论 |
| 来源与日期 | Q07–Q11 | 段落定位、多报道同事件、冲突与报道日期、月精度 |
| 范围 | Q12–Q16 | 分类、日期边界、附件冲突、同名实体、不得自行扩大范围 |

| 无资料 | Q28–Q32 | 不编价格／许可证、未收录不等于不存在、避免泛化、空范围 |
| 权限与异常 | Q33–Q37 | 来源注入、网络／宿主隔离、取消、管理员写入、非法引用 |
| 记忆 | Q38–Q40 | 逐次授权摘要、清除后不带旧内容、本轮要求覆盖偏好 |

不带日期的分类统计包括全部 12 个独立事件。按已核验的日精度统计，2026 年 9 月只有 7 条；报道日期未核验、日期未知、月精度和冲突日期均不算入日统计。Q23–Q25 的两期分别是 9 月 3–9 日和 9 月 10–16 日，预期 2→4、SDK 0→1、模型发布 1→0。零基期百分比为未知，不用无穷大或 100% 替代。

每题有实际 `request` 模板；运行时另加唯一 `client_request_id`。`as_of` 固定，时区是 Asia/Shanghai。日期必须用冻结时钟，不能随着运行日期漂移。实体 `Orion` 同时映射到公司和 SDK，不能假定单一实体。

## 执行方式和当前缺口

真实对照需先把这份样本装入独立随机 `radar_test_` 数据库，并在相同来源、范围、供应商、模型和最大输出设置下分别运行现有简单问答和新 Agent。应用实际路由、工具、配额、引用校验及流式协议均需参与。禁止把测试预期放入模型提示词。

Q35 在第一个非空流式片段后由客户端取消，检查草稿保留、终态未完成且没有自动重试。Q37 用固定非法引用的提供商夹具测试发布门禁。这两题需单独报告，不伪称其答案来自真实模型。Q39 包含浏览器清除和刷新步骤，不能只在服务端构造一个没有历史的请求来冒充验证。Q38 要先展示摘要并明确选择一次，下一次请求消费选择，再验证后续请求不自动附带。Q21 必须实际使用隔离 Python，并保留输入数据集、代码和图表文件。

隔离库样本装载器、单次 SSE 答案采集器与只读账本计量已实现，见下节；装载后的真实仓储核验仍待 Ubuntu 执行。尚待实现／执行：组合这些部件的真实双路径批量运行器、上述客户端场景的自动采集、实际答案、人工复核、失败修复后的回归。现有生产入口→pi→PostgreSQL→真实 gVisor→授权文件下载联合用例已单独准备，但其新测试补丁尚待批准同步 Ubuntu，不能算作通过。

真实收费批量对照需单独确定调用和 token 上限并取得授权。此前最多三次的兼容性验证授权不覆盖此基线；离线检查和生成模板不会发起任何模型请求。

## 生成与填写评审记录

在仓库根目录执行：

```powershell
uv run --project backend python scripts/research_quality.py validate
uv run --project backend python scripts/research_quality.py template --output .run/quality-review-v1.json
uv run --project backend python scripts/research_quality.py score --results .run/quality-review-v1.json
```

输出文件使用独占创建，避免覆盖已有人工评审。新模板的两组各 40 个 `execution`／`review` 都是 null，评分应报告 incomplete 并返回退出码 2。未完成不是质量失败率为零，也不能被记为通过。

每个 variant 的 `configuration` 至少记录 provider、model、max_output_tokens、code_revision。每题 `execution` 存真实 status、answer（失败时为草稿）、最终正式 citations、metrics，以及需要的 client_checks。metrics 包含 model_calls、input_tokens、output_tokens、first_token_ms、duration_ms；未提供的用量或无法测得的延迟明确填 null，不能从文本长度推算。计量来自实际请求／账本；首次内容计时排除仅状态提示的 SSE 帧。

每题 `review` 必须由实际复核者填写 reviewer、notes、task_completed、all_factual_claims_reviewed、claims 和 citation_checks。示意结构：

```json
{
  "reviewer": "填写实际复核者",
  "notes": "逐项说明预期结果是否达成，缺失或不支持的结论也要记录",
  "task_completed": false,
  "all_factual_claims_reviewed": true,
  "claims": [
    {"text": "一条原子事实主张", "supported": false, "evidence": "对应段落或数据与不支持原因"}
  ],
  "citation_checks": [
    {"index": 1, "located": false, "locator": "事件 ID／版本／段落，或数据集／范围／分析代码的复核记录"}
  ]
}
```

这是格式示例，不是本项目的实际评审。引用定位需逐项检查原始 ID、版本、段落、摘录与摘要；统计引用需核对范围、单位、日期口径、数据集和图表。语义复核对这份小样本的所有事实主张进行，不以存在一个有效引用就判整段话正确。拒答／澄清可以没有事实主张，但要说明其为何符合题意。

## 评分与发布门槛

- 任务完成率分母固定为每组 40 题，原要求至少 90%。缺题、重复题、未执行、未复核不能通过。模型回答、故障注入、浏览器场景同时分组报告。
- 正式引用定位有效率必须 100%；结论和来源的语义支持率至少 95%，按原子事实主张计数。没有任何可复核主张／引用时不生成虚假的 100%。
- 权限、取消、记忆及关键范围题不得失败；这些项不会因为总分仍达到 90% 被掩盖。正常问题的 failed/cancelled 草稿不能判为任务完成。
- 旧／新结果必须来自相同模型条件。新 Agent 还需任务完成率严格高于旧路径，定位和语义率不退步，才满足本工具保守的质量切换条件；持平时保留旧路径，报告具体差异再决定。
- 模型调用、已知 tokens、未知用量题数、首段／总耗时的 p50/p95 分开报告。未知值不当作零秒或零 tokens。
- 即便 `quality_release_eligible=true`，仍只代表质量门槛；生产隔离、公开访问、备份恢复和回退必须另有证据。

评分器回归使用的虚构答案和虚构评审仅验证评分行为，永远不进入真实结果文件。当前 12 项离线回归通过，真实旧／新结果均尚未填写。


## 采集部件的实现状态（2026-09-16）

`scripts/research_quality_seed.py` 默认只打印装载计划，不连接数据库。`--install` 才读取专用 `RADAR_QUALITY_DATABASE_URL`；它不会读取应用 Settings 或通用 DATABASE_URL。目标必须是 loopback 上的 `radar_test_` 加 32 位小写十六进制随机名，并核对实际连接库名和候选迁移版本。既有事件、来源、实体、文章、证据、模型调用或问题额度记录任一非空则拒绝；没有清空、覆盖或删除操作。整个装载在一个事务内，失败回滚，合成来源全部 disabled。

```powershell
uv run --project backend python scripts/research_quality_seed.py
# 真正装载前由隔离测试 harness 创建并迁移随机测试库，另行设置专用连接变量。
uv run --project backend python scripts/research_quality_seed.py --install
```

默认演练生成 12 事件、3 实体、5 别名以及各 14 条来源／文章／版本／证据。搜索文本使用实际 CJK 索引构造方法。`test_research_quality_corpus.py` 已准备真实仓储核验：全部题目的范围总量、六分类、时期比较、同名歧义、14 段证据定位，以及重复装载必须拒绝。该 PostgreSQL 用例未在本机执行，默认明确跳过；本地模拟连接测试不能证明实际数据库验收完成。

`scripts/research_quality_capture.py` 是供隔离运行器调用的库，没有默认地址、密钥或自动联网入口。每次只发送一个问答请求，不重试。它实时解析旧／新 SSE，处理中文跨字节切分、回答重置和终态；首段内容时间不以 status 提示代替。取消在第一个内容 token 后关闭响应，保留草稿，不读取后续结果。断流、非法帧、失败或终态后继续输出都不能发布正式引用和产物。它记录客户端观察到的取消，但不会凭客户端关闭就宣称服务器已清理或没有额外模型尝试。

`scripts/research_quality_usage.py` 只允许随机测试库，使用 repeatable-read 只读事务，以匿名 owner 和 client_request_id 定位父问题；旧路径与 Agent 各按实际关联键查询模型账本。返回已结算的调用尝试数，**不表示供应商确认收费的次数**。未知 tokens 保持 null，已知部分另列；尚未结算的请求不能用中间值作为最终计量。它不读取 input_charge/output_charge，因此不会把预留额度当成实际用量。账本与客户端捕获结果需由运行器结合；真实提供商是否重试还须对照请求观察记录。
