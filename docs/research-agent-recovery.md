# Agent 恢复包与恢复验收

状态：2026-09-16，本地完整性校验已实现，独立备份采集、数据库恢复和切换尚未完成。本文补充既有 P5 方案，不降低原验收要求。

## 当前工具实际保证什么

`radar.recovery_bundle` 只处理操作员已经捕获的文件，不连接数据库、Docker、网络或模型，不是 Agent 工具。`seal_bundle` 创建新目录并复制文件，保留密钥原始字节；已有目标一律拒绝覆盖。失败目录可能保留，但没有完整验收记录时不能用于恢复。

包中必须包含 PostgreSQL 自定义格式 dump、源码归档、镜像归档和十份既有凭证。使用语义检索时，镜像与两份固定模型文件必须一同归档。后台模型配置可选，但已配置的部署在采集阶段必须显式包含它，不能靠可选字段判断它不存在。

清单记录源码提交、不可变镜像 ID、schema 0013、导出的 PostgreSQL 快照标识及时间，以及事件、证据、公共请求、模型调用和预算预留六张表的行数与摘要。每个文件必须有长度和 SHA-256。身份与额度 HMAC 密钥不能重新生成、去空格或转换换行。

恢复前必须提供另存于可信清册的清单摘要。不能读取待验证包自己的摘要作为验证依据。校验拒绝遗漏或额外文件、符号链接、重复 JSON 键、越界路径、非法类型、摘要或长度变化。大文件按块读取；清单有大小上限。Linux 写入还会同步文件和目录。

只读校验命令（在有项目 Python 环境的可信操作员终端运行）：

```sh
uv run --project backend python scripts/verify-agent-backup.py \
  /mnt/radar-backup/recovery-YYYYMMDD \
  --expected-manifest-sha256 <单独保存的清单摘要>
```

成功输出仍包含 `database_restored: false`。工具不解包源码、不导入镜像、不执行 SQL、不启动服务。`PGDMP` 头和文件摘要只能验证格式入口与字节一致性，不能证明数据库或镜像真的可以恢复。

## 操作员边界与存储

当前封装函数要求调用方提供可信、私有、不会被其他用户改写的捕获目录和目标父目录。它不替代 Linux 操作员权限与父目录所有权检查。Windows 单元测试不证明 Linux 的权限、UID、目录同步和防链接语义。

`independent_destination` 要求备份使用不同于项目、数据库卷和密钥目录的文件系统，并拒绝放到这些目录内部。捕获入口必须从实际 Docker 卷信息取得数据库路径，不能传入无关目录以通过检查。不同文件系统也不一定是不同物理故障域，操作员仍须确认磁盘或备份主机独立。

本次只读检查 Ubuntu：仅见 `/dev/sda2` ext4 系统盘承载项目，另有安装光盘；未发现独立可写备份挂载。没有在系统盘创建一份目录后称其为独立备份。独立存储位置待用户提供。

恢复包包含凭证和可能的用户数据，应放在受控、限制访问的备份存储中。当前工具未实现加密、远程传输或密钥托管；不能把包当作可公开下载的产物。

## 后续采集与恢复步骤

1. 可信捕获入口核对活动 Compose 项目、容器身份、实际卷位置和独立存储；不接受模型传入的 shell、Docker 参数或数据库地址。
2. 保持只读 repeatable-read 事务并导出 PostgreSQL 快照；dump 与六表指纹必须使用同一个快照。固定 UTC 和稳定的行序列化/主键排序，才能在恢复后比较。捕获失败必须结束事务并留下未封装状态。
3. 导出实际运行镜像的不可变 ID，归档对应源码、既有配置与原始凭证；核验归档内容和版本对应关系，再封装文件，并将清单摘要写入独立可信清册。
4. 只恢复到全新的项目、数据库实例和卷。默认不启动 API、worker、调度或公开 Python。先验证包，再安全处理归档、导入镜像和数据库，重新核验 schema、表指纹、角色权限、证据关系及身份/额度密钥。
5. 使用合成请求检验同 IP 的 48 小时/20 次额度、追问扣额、幂等、跨用户拒绝和未知用量预留。清单里写着 20 行不是这项验收的替代品。
6. 切换前隔离旧入口并停止旧 API、worker、调度与维护写入方，处理在途任务，确认不会有双 worker。独立数据库上的锁不能互相排斥，不能只检查新实例的锁。
7. 完成真实恢复、切换与旧助手回退，记录恢复点、耗时、配额前后值、服务状态和残留任务，才可通过 P5。

## 恢复点不能隐去

快照只能恢复捕获时点的数据，不能保留之后的请求与扣额。恢复旧快照后直接开放问答会重新发放部分额度，违反既有要求。正式方案需补齐受验证的 WAL/PITR 或切换前一致性追平；恢复点之后的账本无法确认时，应保持公开入口关闭，不能宣称额度无损。

## 当前验证

17 项本地单元测试通过；Ruff 和两个源文件的 Linux 平台严格 mypy 通过。用例覆盖同长度篡改、独立清单摘要、缺失/额外文件、已有目录保护、路径穿越、快照字段、非法 dump 头、重复 JSON 与模型文件配套。

这些测试使用明确标记的合成字节，并非可恢复的 PostgreSQL 或 Docker 制品。本次没有捕获线上数据库或密钥，没有真实恢复，没有修改线上开关，也没有调用付费模型。
