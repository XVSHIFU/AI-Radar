# 实施方案续篇：管理员后台与后续交付

更新：2026-09-15。此文补充原《AI-Radar-Implementation-Spec-v1.0.md》，保留公众免注册、
AI 动态首页、独立统计页、浏览器会话历史的既定设计。按依赖顺序逐步交付，不把部分功能通过等同 P0 完成。

## 已完成基线

Ubuntu 开发环境、PostgreSQL16+pgvector、持久采集队列、冻结原文版本、Flash事件提取、
结构/逐字引文校验、真实事件浏览统计已打通。模型限定 deepseek-flash，提供商硬额度控制。
真实 JSON 问答已接通并通过 Flash 实测；真实 SSE、向量检索、跨来源事件归并和事件发生日期质量仍待完善。
当前状态与旧文档中的“没有模型/无事件”历史描述不一致，以本续篇及最新验收证据为准。

## 阶段一：/ingest 管理员后台（已交付）

原方案已有管理鉴权与来源/采集记录，补齐完整后台工作流：

1. 管理门禁：进入 /ingest 先验证管理口令；HttpOnly 会话、过期、注销、失败限流。
   服务端所有管理接口独立鉴权，cookie 写操作校验 CSRF；页面隐藏不能代替鉴权。
   公众事件和统计保持免登录，后台不显示研究助手，也不能通过 demo 参数绕过权限。
2. 来源：列表、启停、新增和编辑自定义 RSS、健康探测、最近成功/失败记录。
   内置归档来源与适配器绑定，首阶段名称/入口只读，避免编辑后定时器使用旧地址。
   停用阻止后续任务抓取；已在执行的网络请求可完成。保留原文和历史，不硬删除来源。
   探测只判断入口可访问和格式可解析，不能把 HTTP200 当作正文采集及发布全部成功。
3. 采集：查看真实运行记录，手动提交明确选定的已启用来源，复用幂等请求机制。
   自定义 RSS 首阶段可手动采集；内置历史回填继续由现有定时脚本运行。
4. 模型：查看配置状态，更新服务端密钥、启停和输出上限。
   当前供应商/接口/模型固定为已授权 DeepSeek 官方 Flash；后续多供应商另做适配。
   密钥不读回浏览器，不存浏览器本地存储，不入 Git；服务端受限文件原子保存。
   连接检查与短回答测试分开；只有短回答测试触发生成，并进入调用账本。
   显示实际调用数和 token，用量缺失保持未知，不推算费用。
5. 验收：未登录/错误口令/注销/过期、CSRF、密钥不泄露、SSRF、来源开关实际生效、
   配置被后续提取任务使用、测试失败状态和 token 记录；桌面手机浏览器检查。
   先在现有 Ubuntu 私有网络开发环境使用，公网部署阶段配置 TLS 和 Secure cookie。

## 阶段二：真实研究助手最小闭环

先以明确页面范围/事件附件为边界，检索库内事件及冻结 Evidence，生成带引用的回答。
规则可以确定日期/分类/实体时不调用模型解析；复杂问题才考虑受 schema 约束的计划。
不让模型生成 SQL，不静默扩大范围，不把模型故障当成“没有资料”。

- 设定有限事件/证据与历史上下文；真实匹配总数、取回数、总结数和覆盖范围如实显示。
- 引用编号由服务器分配，URL/段落/引文从数据库读取；未知引用拒绝。
- 所有在线调用入账，失败/取消/未知用量区分；避免自动重试付费请求。
- 前端已有 JSON 和模拟 SSE；先真实 JSON 完成闭环，再补真实 SSE、取消和中断恢复契约。
- 小范围真实 Flash 冒烟测试与离线模拟回归分开；不依赖模型自己打分作为唯一验收。

## 阶段三：数据可信度与检索

1. 日期区分报道日期与事件发生日期，补依据/精度/未知/冲突，不把9月报道的6月发布算9月新发布。
2. 跨报道事件归并、同机构不同型号/版本不误合并、原文更新与引用版本稳定。
3. 中文全文检索与索引版本；embedding profile/维度/revision、故障降级、RRF和结果快照。
4. 语义证据核验与人工样本抽查；“摘录存在”不等于“主张被独立证实”。
5. 扩展受控来源和归档覆盖，明确失败/限流/尚未覆盖的时间段，不声称8–9月互联网全量。

## 阶段四：验收与运行

逐题绑定 P0 回归；历史 gold/旧接口兼容仍等待原站标识或冻结材料，先保留合成结构回归。
抽查至少5个完整来源和100个标准事件的质量，不仅统计数据库条数。
补充后台操作审计、多实例会话/限流持久化、生产TLS、备份恢复和运行告警。
没有公网部署目标/域名时不自动扩大网络暴露范围。
