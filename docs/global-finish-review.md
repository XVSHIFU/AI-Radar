## material_fixes

1. **必修：恢复 B 堆叠面积的可见分类图例。**
   复现：/ask → 近7天 → B 堆叠面积；desktop-b.png 与 mobile-b.png 都显示六个空白按钮。源码 `frontend/src/style.css:999` 将图例按钮文字设为白色，而 `.chart-area--0…5` 只声明 SVG 的 fill/stroke，未给 HTML 按钮背景赋色，因此保留通用白底。
   具体改法：给图例明确深色文字，并以与各面积一致的实色小色块表示类别；或为按钮显式赋对应背景色并验证文字对比度。优先小色块+深色标签，保留现有按钮点击筛选、焦点和最小触摸高度。确认六个中文分类在桌面和390px宽度均可见，并与六个面积对应；不能仅用 textContent 存在代替像素检查。

2. **必修：让手机用户知道并能理解横向图表。**
   复现：390px → /ask → 近7天 → A/B/C。mobile-a.png 没有右端日期，mobile-b.png 看不到末日及零值尾段，mobile-c.png 只有部分日期列。源码 `frontend/src/style.css:988` 把 A/B SVG 固定为720px并包在 overflow-x:auto 中；热力图列也超出窄屏。横向滚动本身可以保留，但当前没有说明，读者容易把截取部分当作完整结果。
   具体改法：为实际溢出的图表提供就地短提示“左右滑动查看完整日期”，确保滚动区域能由键盘聚焦和操作，并让分类/日期参照在浏览时保持可辨。A/B 若采用专门手机坐标布局或自适应宽度，须同时保持类别、日期和数字可读，避免把720px整体缩成无法辨认的小图。C适合保留横滚并固定左侧分类列。确认手机可触达最后日期，且无需猜测被裁掉的含义；不要把整页没有横向溢出视为此项通过。

3. **必修：去掉正式界面仍保留的 hover 下划线。**
   此项为源码判定，14张静态截图没有 hover 状态，不能声称已有浏览器验证。复现目标：首页月份按钮、首页事件标题，以及 /ask 匹配事件标题。`frontend/src/home-timeline.css:64` 的月份 hover 规则及 `:162` 的事件标题 hover 规则仍声明 text-decoration:underline；`frontend/src/style.css:866` 的统计事件标题也仍在 hover 时加下划线。没有找到生效范围内的后续取消覆盖。首页清除条件还在 `style.css:834` 保留常态下划线。
   具体改法：移除上述正式界面的下划线声明，用现有深蓝文字或轻底色提供反馈，保留 focus-visible 轮廓。确认首页月份、事件、清除，以及统计事件标题 hover 时均无下划线；键盘 Tab 的焦点仍可辨。这是原请求的遗漏，不是新增审美修饰。
