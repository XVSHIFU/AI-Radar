## 本地新增：控制器健康门槛

`sandbox_controller.py` 是仅供操作员启动的单进程入口。仅监听 loopback，凭证来自操作员私有文件，无公开 API 配置或数据库加载。进程锁避免同一主机重复控制器；没有将 Docker 权限交给模型。

启动核对固定 runsc 二进制摘要、root 所有权与不可被普通用户写入的路径、Docker runtime 配置和固定本地镜像。只清理符合既有所有权和过期条件的遗留容器；尚年轻的任务留给独立 watchdog，并拒绝启动就绪。不会猜测其他任务可以删除。

运行中每五秒检查独立 watchdog、runtime、镜像与执行器清理状态。健康证明超过十二秒失效；任一检查失败保持拒绝，需操作员排查后重启。认证的 `/health` 与实际执行共享门槛，公开 API 在扣问题额度前查询健康状态。

当前入口使用宿主 systemd watchdog，**不是最终 Compose 的 watchdog 方案**。Compose 必须提供独立、可验证的清理进程状态，不能伪造健康字段。

本次本地 `test_research_*`、`test_sandbox_*`、`test_python_preflight_quota.py` 共 171 项通过；真实 pi 子进程测试开启，模型上游为夹具。四个受影响后端模块按 Linux 平台严格 mypy 通过，Ruff 通过。测试集合与之前的 191 项切片不同，不将两者相加计数。此结果不能替代 Ubuntu 实际入口验收。
