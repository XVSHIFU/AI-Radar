## 已完成的本地控制面代码

- `radar.sandbox_controller` 保留宿主 loopback / systemd 入口，新增可注入的独立 watchdog 检查。
- `radar.sandbox_container` 提供容器入口，固定内部端口 8092；只读取操作员准备的凭证文件、固定沙箱镜像 ID 和控制器锁。
- `radar.sandbox_watchdog` 是单独进程。启动时先取得自己的锁并成功执行清理，再提供认证的 8093 健康接口。每五秒执行一次受限清理；单次最长二十秒；只使用现有的所有权与过期判定。
- 健康信息必须包含协议版本、独立角色、就绪状态及不超过三十秒的成功清理时间差。控制器只访问固定内部地址，拒绝重定向、压缩、超量、损坏或过期响应，整个请求有三秒截止时间。
- 任何清理故障立即锁定为不可用。后续继续尝试清理，但成功清理也不会自动恢复就绪；需操作员查明原因并重启。Docker 的 unhealthy 状态本身不能当作已经完成自动重启。
- 关闭时等待监控任务退出并释放进程锁；锁文件不能删除重建，否则会绕过原 inode 上的锁。
- 主机和容器共用 `sandbox_credentials.read_service_token`：以不跟随符号链接、不阻塞管道的方式打开，再对同一文件描述符检查普通文件、当前 UID 所有权、无 group/other 权限、长度及随机 token 格式。随后从这个描述符读取，避免“检查路径后路径被替换”的竞态。

这些入口只供可信部署控制面使用，没有登记为模型工具。模型仍不能启动这些进程、读取其凭证、操作 Docker 或调用 shell。

## 完整编排仍要实现的边界

| 服务 | 可以接触 | 不应接触 |
| --- | --- | --- |
| 入口代理 | 静态前端、API 内网地址 | 数据库凭证、供应商密钥、Docker socket |
| API | 数据库应用身份、后台模型配置、pi、控制器的窄接口 | Docker socket、宿主目录、任意模型命令 |
| 采集 worker | 采集数据库身份、来源网络、所需模型配置 | Docker socket、用户文件产物、pi 控制凭证 |
| pi 运行时 | 固定 Agent 文档、认证的 API 工具代理 | 直接数据库连接、供应商密钥、宿主挂载、Docker socket |
| 沙箱控制器 | Docker socket、固定 runtime 的只读校验文件、私有 token、控制器锁 | 业务数据库、模型供应商密钥、公开端口 |
| 独立 watchdog | Docker socket、单独健康凭证、watchdog 锁 | 业务数据库、供应商密钥、代码执行 HTTP 接口、公开端口 |
| 模型生成的 Python | 本次冻结的数据集、有限内存和临时空间 | 网络、凭证、宿主挂载、Docker socket、外部持久文件 |
| 数据库 | 专属数据卷和受限内网 | 对公网暴露、模型直接访问 |

控制器和 watchdog 持有 Docker socket，属于可信宿主控制面，不能宣传为“拥有这些权限的进程也无法越出 Docker”。真正不可信的模型代码只进入无 socket、无宿主挂载、无网络的 gVisor 任务。

现有 `compose.prod.yml` 仅有入口代理，`docker-compose.yml` 主要提供数据库。因此它们目前不满足上表的全栈隔离目标。

## 接线与迁移顺序

1. 为各服务准备固定依赖与镜像摘要、独立非 root 身份、只读根文件系统、有限 tmpfs 与资源上限。镜像中不能包含 `.env`、数据库、私有配置或测试凭证。可信控制器镜像需要 Docker CLI，普通 API / pi 镜像不需要它。
2. 编排私有网络：数据库、工具代理、执行控制面分别限制连通；控制器和 watchdog 不发布宿主端口。API 是公开问答请求通往工具的唯一受控路径。
3. 操作员准备固定路径的私有 token 文件。文件必须属于容器内实际 UID，权限 0400 或 0600；不能假定 Compose 对文件挂载的 uid/gid/mode 声明会改写宿主文件权限。凭证不出现在 argv、健康响应或访问日志中。
4. 控制器和 watchdog 使用持久的可信锁目录。切换宿主模式与容器模式前必须停止旧控制器，或者显式共享同一个锁 inode；两个不同路径的锁不会互相排斥。锁目录不能暴露给 API、pi 或生成的 Python。
5. 固定 runsc 文件只读挂载到预期路径，镜像中的路径祖先保持 root 所有且普通用户不可写；Docker daemon 的 runtime 仍须使用相同固定路径和参数，不能只校验容器里的一份无关文件。
6. 先启动独立 watchdog 并完成实际清理，再启动控制器。真实验证凭证权限、重复实例、过期任务、watchdog 崩溃、控制器崩溃、Docker 不可用和重启后的就绪拒绝。失败后的操作员恢复也要记录。
7. 先只使用临时策略、合成数据和模型夹具完成公开入口联合验收，之后再讨论收费质量评测与正式开关。主机上已通过的测试不能替代容器网络与挂载验收。

## 备份、恢复与切换的完成标准

- 独立备份位置必须在部署目录和活动数据库卷之外；另一台使用同一个数据卷的容器不是备份。备份包含数据库、必要的身份/配额 HMAC 配置、后台模型配置、迁移版本、源码与镜像版本清单及校验摘要；密钥归档只在操作员的受控存储中处理。
- 恢复至独立卷和独立数据库实例，默认不启动采集、不接收公开请求、不启用 Python。恢复过程先验证摘要和迁移版本，再核验事件/证据关系、用户隔离、额度账本、调用账本与窗口时间。
- 切换前阻止旧入口接收写请求，停止旧 API 与 worker，等待或明确终止在途任务，并确认旧实例已被隔离。两个独立恢复数据库之间的 advisory lock 无法防止双 worker；必须在部署层保证单一活动实例。
- 同一 IP 的 48 小时/20 次计数、幂等请求与签名身份必须保留。恢复不能重新发放额度。内存中的临时文件链接可以失效，但 UI 必须如实提示，不能指向其他用户的文件。
- 使用合成请求确认新实例可用后才切换入口。演练中记录切换时间、停止/恢复实例、额度前后值和残留任务；回退旧助手时同样先停止新写入方，不能让两个 worker 同时运行。
- 完成一次真实的独立恢复和回退，并保留机器可读证据后，才可将 P5 标记完成。当前上述步骤尚未执行。
