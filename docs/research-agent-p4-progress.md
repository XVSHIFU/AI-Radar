## 会话记忆（已同步 Ubuntu 候选）

“历史会话”中的“会话记忆”入口沿用 A 布局、E 时间线、主题和字体。仅处理当前浏览器中当前会话的消息，演示轮次不会混入真实请求。最近三轮上下文仍按完整问答配对，较早轮次可在本地生成提取式摘要。没有后台付费压缩，也没有新增服务端会话全文数据库。

摘要记录问题片段、原回答片段、原范围、引用线索和未解决状态。只有 completed 且无 error 的成对问答可进入；失败、中断、孤立回答不能被整理成事实。没有引用的回答只留下待解决问题，不保留其结论。历史 citation 编号不是本轮正式引用，模型需要重新查询。

摘要整体 JSON 包括元数据与转义后字节数受 1,200 字节限制，沿用当前预算守卫的一字节保守估计；这比按四字符估算 1,200 tokens 更严格，适用于中英文和控制字符。重要数字与历史结论始终标为待重新查证。

### 逐次授权发送

首次自动附加旧摘要的补丁被自动审批拒绝，原因是可能向外部模型发送未经明确授权的敏感历史内容。该补丁未写入。改用并通过审批的实现：

- 默认没有摘要发送选择，选择状态不写入 IndexedDB、不从聊天文字推断。
- 用户先查看本地摘要，再勾选“仅下一次使用这份摘要”。界面明确说明发送给后台配置的模型服务。
- 勾选时冻结所展示的副本，下一次发送立即消费；取消选择、切换会话/模式或开始新轮次都会清空选择。
- 后端只有同时提供合法 memory 和 `memory_consent=send_once` 才接受；直接构造提示时再次检查。拒绝缺少同意或伪造 always 等值。
- 摘要是低信任资料，不能改变当前范围、权限、工具或引用来源。模型无法要求前端替用户勾选。

常见凭证形态在摘要预览中遮盖，链接正文不复制；这不是通用敏感信息识别器，逐次查看授权仍是必要边界。摘要随请求在内存中处理，不另存长期副本。

### 偏好和清除

偏好只有语言 auto/zh/en 和长度 concise/detailed 两个枚举，用户必须点击“记住偏好”才保存到当前浏览器、当前会话；支持查看和删除。不能保存任意系统指令。用户本轮明确要求优先。

清除上下文保留可阅读的旧消息，但设置持久的排除边界；后续最近历史和摘要都排除边界之前的消息，刷新后仍成立。边界标识缺失时默认不恢复旧上下文。删除会话沿用既有浏览器删除行为。清除上下文或偏好不会重置 IP 额度。

新旧问答路径都接受明确附加的摘要和受限偏好。新增字段为空时从请求指纹中去掉，保持已存旧幂等账本的指纹兼容；实际附加内容或偏好变化会改变指纹，不能用同一键悄悄换上下文。
