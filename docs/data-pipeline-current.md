# 数据从哪里来，模型在哪一步参与

当前使用 8 个配置过的官方公开来源：Hugging Face、arXiv cs.AI、Google Research、
AWS Machine Learning、NVIDIA Technical Blog、OpenAI、Anthropic、DeepSeek。
定时脚本读取 RSS 或官方归档页，按发布日期筛选，再由 worker 请求正文。
没有使用模型凭空补写原站文章，也没有用搜索模型回答充当原文。

| 阶段 | 当前实现 | 是否调用模型 |
| --- | --- | --- |
| 发现、下载 | RSS/归档分页，日期筛选，抓取正文，限流重试 | 否 |
| 原文保存 | URL 去重，保存不可变 ArticleVersion、段落与内容哈希 | 否 |
| 事件整理 | 中文标题、摘要、分类、重要度、实体、候选引文 | DeepSeek Flash |
| 结构校验、发布 | 检查 JSON 字段及逐字引文，事务写事件和 Evidence；失败隔离 | 否 |
| 页面统计 | 根据库内事件按日期、分类和筛选条件聚合 | 否 |
| 研究助手回答 | 前端会话与事件附件已有；真实问答接口未完成 | 本轮未接入 |

## 与原开发方案的关系

依据项目方案第 6、7、14、16、20 节：

- Source 是渠道；Article 是报道身份；ArticleVersion 是一次保存的原文内容。
- Event 是业务事件，同一事件可以有多篇报道。
- Evidence 指向特定原文版本的特定段落，不能仅有一个网页链接。
- 数据采集、提取、归并和索引独立推进；向量失败不应阻塞普通筛选统计。
- 摘录存在、链接有效、摘录支持主张是三项不同的检查。

目前已打通“抓取 → 保存 → Flash 提取 → 字段与逐字引文校验 → 展示统计”。
以下仍是开发缺口，不能把本轮跑通等同整套方案完成：

1. 事件日期：现在主要用报道发布日期；仍需补 date_basis、真实发生日期提取、
   冲突与未知日期处理。9 月报道可以描述 6 月上线，不能据此断言 9 月新上线。
2. 跨报道事件归并：当前一篇报道通常生成一个事件；同 URL 版本更新会复用事件，
   不同网站报道同一件事尚未完整聚合，统计仍可能包含重复报道对应的事件。
3. 语义证据核验：逐字摘录匹配不等于摘要所有主张已被独立验证；证据保留 unverified。
4. 向量检索、真实研究助手问答、历史 gold 样本和合并审阅仍未完成。

## 中文来源与保存证据

中文来源入口优先用于阅读。保存证据必须继续对应实际抓取的语言和版本：
英文原文产生的英文引文，不应改名为来自中文网页。DeepSeek 可以同时提供
“阅读中文版”和“查看采集原页”，无需重新调用模型或修改历史证据。
