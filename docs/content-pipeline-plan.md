### 本轮实现与使用

管理员登录 `/ingest` 的内容工作台，选中最多 5 篇冻结文章，复制或下载任务并交给自行选择的网页生成器，再粘贴 JSON 结果。逐篇查看错误、修改草稿，确认后发布，或将无关文章标为跳过。导出按 48 KB 上限截取原文段落，并保存实际导出的引文范围；手动流程不调用本站模型 API。接口、字段与错误约定见 [内容工作台 API](content-workbench-api.md)。

自动模式须另行配置内容专用 API Key 和非零每日篇数、输入及输出 token 上限，再显式选择本批文章。默认关闭、自动发布默认关闭，每篇最多一次模型调用，并发 1。内容 pi Agent 只生成草稿，无 shell、Python、数据库写入或管理员工具；服务端完成校验和发布。结果或用量未知时保留预算预留、暂停队列，不自动重试或切换收费供应商。

隔离验证使用了一篇真实已采集公开文章的冻结样本，完成手动导入与发布；这不是生产库的新发布。本轮未产生付费模型调用。最终针对性检查为内容 PostgreSQL 6 项、原提取回归 7 项、迁移 1 项及内容单元测试 3 项；完整 Node 运行时 18 项，以及后续长提示边界与容器入口合计 5 项针对性检查通过。此处只记录受影响范围，未宣称全站质量基线通过。参考数据的隔离与来源种子操作见 [受控接入说明](content-reference-import.md)。

## 2. 一条公共处理流程，两种生成方式

以下保留原设计要求；现行实现和验收边界以上文及 [内容工作台 API](content-workbench-api.md) 为准。

```text
脚本采集 → 冻结正文 → 去重与规则初筛 → 内容待办
                                      ├─ 手动：复制任务 → 网页生成 → 粘贴导入
                                      └─ 自动：指定模型额度 → 内容 Agent 生成
                         同一草稿 → 服务端校验 → 预览 / 发布 → 公共事件库
```

两种模式共用原文、任务 ID、草稿格式、校验和发布服务，可以随时切换。已发布内容和已完成草稿保留；切换不会重新处理整库，不会将任务偷偷改成收费调用。

### 原定脚本职责（仍待逐项落地）

- 从已启用、已验证的 RSS/Atom 或原文页面取得标题、来源链接、报道时间、正文段落，保留冻结版本。
- 先用规范 URL 与正文哈希去重，跨站转载保留出处。同名模型的不同发布不能仅因标题相似就合并。
- 用来源栏目、实体和动作词表建议分类，明确无关的内容先筛掉；有歧义的留待确认。聚合源只提供线索，原站正文才进入证据流程。
- 优先使用已有简介或关键句作为“原文摘录”；生成的中文摘要单独标记来源方式。英文摘录不能伪装成合格的中文摘要绕过现有发布校验。
- 报道日期与事件发生日期分开。正文不明确的事件日期留空，不把抓取时间、报道时间自动视为发生时间。

### 手动模式（默认）

1. 管理员在内容待办勾选文章。第一版建议每批最多 5 篇；长文按实际总长度减少篇数。
2. “复制摘要任务”或“下载任务文件”导出固定提示词、任务编号、原文和段落标记。只导出所选公开文章，不混入密钥或公众会话。
3. 管理员自行粘贴到 DeepSeek 或其他网页聊天工具；生成器不限供应商。本站不托管网页账号，也不依赖网页会员额度自动转换成 API。
4. 回答粘贴到“导入结果”，支持常见 JSON 代码块外壳，逐篇指出缺字段、未知任务、重复结果和引文不符。
5. 成功项显示预览，失败项可修改或重新导出。再次导入同一结果不重复发布、不覆盖更新的草稿。
6. 管理员确认发布。手动路径全程不自动调用模型修复。

模型主要返回任务编号、中文标题、短摘要、六类之一、原文段落标记；实体、重要度、日期等可由脚本建议并在预览中补齐。目标摘要约 80–160 个中文字，仍沿用首页最多四行的展示规则，不将字数等同于固定行数。

### Agent 自动模式（显式启用）

在同一内容工作台选择“Agent 自动”，填写或选择**内容处理专用**的模型配置：

| 配置 | 行为 |
| --- | --- |
| 提供商 / 兼容协议、Base URL、模型名、API Key | 复用现有配置校验与密钥保护；独立保存，不覆盖公众助手模型 |
| 本批篇数、每日文章数、每日输入 / 输出 token 上限 | 上限缺失或为 0 时不启动；默认建议单批 5 篇、并发 1 |
| 每篇模型调用 / 输出上限 | 第一版默认每篇最多 1 次模型调用；不付费自动重试或自动修复 |
| 运行范围 | 仅本批选中文章；可后续显式选择来源和时间范围，禁止默认全库回填 |
| 校验通过后自动发布 | 默认关闭；打开后由可信发布服务处理合格结果，异常仍留待审 |

“空余额度”指供应商允许程序使用的 API 额度或明确提供的兼容服务额度。网页免费聊天/会员额度不自动等于 API 额度。余额接口不存在时不假装能读到账户余额，使用本地限额控制；有 API Key 不代表自动允许消费。

第一版复用现有 pi 核心及供应商适配，采用独立内容任务和提示规范；不另起一套万能 Agent。公众研究 Agent 仍只读，内容 Agent 也只生成草稿，可读所选冻结文章，**不获得数据库写入、任意网页访问、shell、Docker 或管理员工具**。事务入库、审核与发布由后台业务代码完成。本任务不需要 Python 工具。

开始调用前持久化认领任务、记录模式/模型/提示版本并预留 token 上限；返回后按实际 usage 结算。费用不明或超时结果未知时保留“未知”状态和保守预留，不再次自动请求。余额不足、限流、认证失败或用量达到上限即暂停剩余队列，不自动切换其他收费供应商。切回手动后未调用的文章可以继续导出。

自动内容处理使用独立用途账本与管理员批次权限，不占用公众 IP 的 5 次额度；也不能借切换模式清空消费记录。模型配置变更只影响新任务，运行中的任务绑定原配置版本。

## 3. 共用数据和校验边界

- 增加内容任务/草稿记录，绑定 `ArticleVersion`、内容哈希、提示/结构版本、模式、认领状态和结果修订；手动导入不能依赖伪造一条 API 消费记录才能发布。
- 手动导出保留服务端映射的任务编号。导入只允许当前管理员可见任务；任务、冻结版本不匹配拒绝，不能相信模型返回的新 URL 或版本 ID。
- 从当前 `ExtractionService._publish` 拆出共用“校验 → 发布”服务；复用实体、日期、引用与归并逻辑。保留来源关系，发布事务幂等。
- 引用逐字定位由服务端检查，但“能找到原句”不代表“语义结论已核实”。不提升原有核验等级、不接受模型自称已验证。
- 六个分类代码保持现有合同；`needs_review` 是处理状态，不新增为公众第七类。
- 建议状态：待处理 → 等待手动结果 / 自动处理中 → 待审草稿 → 已发布 / 已跳过；另外保留校验失败、调用结果未知和预算暂停。免费解析失败不显示成模型调用失败。
- 把采集和生成任务分开启停。先确认采集 worker 不会调用模型，才能恢复免费采集；恢复页面服务不顺带恢复历史收费提取。

## 4. 参考调研采用范围

采用官方源优先、社区中转标识、聚合线索回原站、来源新鲜度监控、分类/动作词表、有限页面变化监控等做法。64 个来源作为候选池，先接通少量可靠官方源，不一次启用全部。

本轮 HTTP/XML 抽检：Hugging Face feed 和 Groq 官方 changelog Atom 均返回合法、有条目的 feed。数据中错误 QID、错列策略、空源与未验证公告页面暂不导入。实体词表需映射到现有类型；同名歧义不能按 Wikidata 搜索第一条直接认定。细节见 [参考资料审查](reference-review-20260919.md)。

## 5. 原定步骤与当前收尾

下表保留原定实施顺序。内容任务、草稿和两种生成路径已上线，生产只读核验通过，写入闭环在隔离库验收；第 5 项剩余同机备份更新记录。更广泛的脚本初筛与免费采集恢复尚未启动，详情见 [内容工作台交付记录](content-workbench-delivery-20260919.md)。

| 顺序 | 任务 | 最小完成标准 |
| --- | --- | --- |
| 1 | 整理参考数据与拆开免费采集 | 修复 8 处 CSV 错列、隔离错误实体映射；少量来源导入默认禁用；明确纯采集不调用模型 |
| 2 | 共用内容任务、草稿和发布服务 | 原文版本绑定、手动/自动共用校验；重复提交只发布一次，公众接口不能写入 |
| 3 | 先交付手动闭环 | 后台选文章、复制/下载任务、粘贴导入、预览发布；至少一篇真实已采集文章走通，零模型 API 调用 |
| 4 | 增加 Agent 自动模式 | 专用模型配置、一次批处理、持久化用量上限、暂停及切回手动；未知结果不自动重复花费 |
| 5 | 小批验收并更新容器 | 验证幂等、错误反馈、限额和手动/自动切换；更新同机备份，先手动模式上线，自动模式默认关闭 |

不为这次内容工作台重跑无关全站测试或大规模模型评测。自动路径首先用夹具测试；真实供应商兼容确有必要时才安排明确小额范围，保存配置不触发隐式测试调用。

参考新规格保留其可用的数据/业务建议；不恢复已取消的旧站兼容要求、20 次公众额度、大规模默认付费评测或独立备份盘门槛。
