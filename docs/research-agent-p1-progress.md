# 专用 Agent P1：公开提问配额

2026-09-16。继承 [专项增补方案](research-agent-v2.md)，旧方案和 Agent 规范包保留。

本阶段将现有问答路径接入配额。pi 工具循环、Python 沙箱、记忆摘要、质量评测与完整容器化仍属于后续阶段，不能称为已经实现。

## 规则与接口

- 同一 IP，精确滚动 48 小时，最多 20 次已接纳问题，追问计入；新建空会话不计。完成但没有资料的查询计一次。模型调用前被拒绝的请求释放预留；模型已开始的取消或未知结果保留次数。
- PostgreSQL `public_ask_requests` 保存 HMAC 化 IP/匿名归属、幂等标识、预留和结算，不存问题正文、原始 IP 或会话令牌。事务锁保证多进程最后一个名额不会超发。
- `GET /api/v1/assistant/session` 初始化 30 天签名 HttpOnly/SameSite Cookie，返回剩余次数及用尽后的最早恢复时间；HTTPS 使用 Secure。匿名 Cookie 是请求归属，不是 IP 限额的替代。
- `/api/v1/ask` 和 `/api/v1/ask/stream` 共用账本。超额返回 HTTP 429、`Retry-After`，发生在 SSE 开始前。跨端点重复请求返回 409，不再次付费，也不向其他匿名会话返回原结果。
- 2 个全局并发、每轮 90 秒；初始预留输入 24,000 / 输出 4,800，结束按已知用量结算，未知保留预留值。当前单次回答适配器仍限制输出最多 2,000，并以 UTF-8 字节加消息封装余量进行保守输入估算；这不是供应商精确 tokenizer。后续 pi 每轮多次调用仍需逐调用预算控制。
- 全站按 UTC 入账日限制输入 200,000 / 输出 32,000，可通过服务端配置调整；跨午夜的运行中预留继续占用预算。后台采集和管理员测试独立记账。
- `PUBLIC_ASSISTANT_SECRET` 缺失时真实付费接口拒绝服务，不退回无限制模式；轮换该密钥会改变匿名归属和 IP 哈希，不能把轮换当作普通重启，备份恢复必须保留密钥与账本。
- 现有 Vite 直连访客入口覆盖客户端转发头，仅写入 socket 对端。API 仅监听回环地址并仅信任回环代理；新增 CDN/反向代理时须重新定义可信链，不能设置为信任所有来源。依据：[Uvicorn 代理配置](https://www.uvicorn.org/settings/#http)、[Vite proxy 配置](https://vite.dev/config/server-options#server-proxy)。

## 已执行验证

- PostgreSQL 隔离工作树、自动创建的临时数据库：8 项通过。覆盖滚动时间边界、最后名额并发、跨进程账本、20 次后拒绝、两种 HTTP 入口共用额度、匿名重建、跨端点幂等、真实用量及取消未知用量。
- 后端相关问答与接口测试：30 项通过；新模块 Ruff / mypy 通过（完整 main.py 存在原有类型问题，不作为本次全部类型通过的声明）。
- 前端测试：45 项通过，含真实 Vite HTTP 代理转发头防伪和初始化失败禁止付费请求。前端类型检查及生产构建通过。
- 1440×960、390×844 浏览器检查：额度提示位于现有主题输入区下方，支持中英文；该项使用模拟额度响应，不冒充线上计数验收。没有调用收费模型。
- 升级前 Ubuntu 数据库备份及独立恢复通过：293 事件、1,145 段可定位证据；备份 `radar-20260915T170135-614634.dump`，数据库仍为旧版本时执行。
